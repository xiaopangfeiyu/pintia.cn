# PTA 题目集关闭时间提取

提取当前账号的活跃题目集名称、关闭时间和链接，按关闭时间排序，保存带时间戳的 CSV（Excel 可打开）与 JSON。浏览器时区设置为北京时间。程序不提交题目、不修改账号数据。

## 安装和运行（PowerShell）

```powershell
cd E:\Project\zju\pintia.cn
python -m pip install -r requirements.txt
python pta.py
```

默认使用本机 Microsoft Edge。首次运行在程序打开的浏览器里登录，然后回到终端按回车。程序保存登录状态到 `.auth/state.json`；之后运行会自动复用登录状态并提取。这里的浏览器与聊天内浏览器独立，需要首次单独登录。

后续可无窗口提取：

```powershell
python pta.py --headless
```

登录过期时，无窗口模式返回非零退出码；请运行 `python pta.py` 重新登录。

如果没有 Edge，可使用 Chrome：`python pta.py --channel chrome`。或先执行 `python -m playwright install chromium`，再用 `python pta.py --channel chromium`。

## 账号密码自动填写（可选）

当登录状态失效时，如果当前进程环境中有 `PTA_USERNAME` 和 `PTA_PASSWORD`，程序会尝试填写并提交登录表单。请通过本机安全的环境管理方式提供，不要写进源码或聊天。可能出现的验证码仍需本人在浏览器完成；提交后需回终端按回车继续。无人值守适用于有效登录状态，不保证过期后的验证码自动登录。

`.auth` 包含可用于登录账号的敏感状态，请仅在自己电脑保存，不分享、不提交到 Git。代码已在 `.gitignore` 中排除此目录及导出结果。

## 输出与失败处理

结果位于 `output/pta-时间戳.csv`、`output/pta-时间戳.json`。每次创建新文件。只有提取条数与页面“共 N 条数据”一致时才输出；分页控件无法识别、关闭时间缺失或页面加载失败会报错，不把部分结果当成完整结果。

当前列表结构依据聊天中实际读取到的 PTA 三个题目集设计。分页与账号密码表单自动提交尚需在本机登录后的实际运行中验证，网站改版可能需要调整选择器。

登录状态复用方式参考：https://playwright.dev/python/docs/auth

## 多用户后端部署规划（尚未实现）

当前程序是本机单用户版，使用一个 `.auth/state.json` 和终端交互登录。以下内容是后续开发规划，现有程序尚不提供 HTTP 接口、多用户隔离或服务器登录绑定能力。

### 用户流程

1. 用户登录自己的业务网站。
2. 首次使用时绑定 PTA，并完成 PTA 登录验证。
3. 后端加密保存该用户的 PTA 登录状态；默认不持久化 PTA 明文密码。
4. 用户点击“获取题目集”，后端建立独立浏览器上下文，加载该用户的状态，提取名称、关闭时间和链接。
5. 保存本次完整提取结果，前端展示最近同步时间和题目集列表。
6. 登录状态失效时返回“需要重新登录”，用户重新完成绑定。失败时保留上次成功结果，并明确标记其同步时间及本次错误。

### 拟定接口

所有接口均要求业务网站身份认证，用户身份由后端会话解析，不信任前端传入的用户 ID。

| 接口 | 用途 |
|---|---|
| `POST /api/pintia/bind` | 发起当前用户的 PTA 登录绑定，返回绑定流程标识和下一步操作 |
| `POST /api/pintia/sync` | 为当前用户创建提取任务，返回 `202` 和任务 ID |
| `GET /api/pintia/tasks/{task_id}` | 查询当前用户的任务状态、结果或错误 |
| `GET /api/pintia/problem-sets` | 获取当前用户最近一次成功提取的结果及同步时间 |

前端调用示例（未来接口，当前不可调用）：

```javascript
const response = await fetch('/api/pintia/sync', {
  method: 'POST',
  credentials: 'include'
});
const task = await response.json();
// 使用 task.task_id 查询任务进度；具体响应字段在实现时确定。
```

### 状态、数据与并发隔离

- 每个业务用户独立保存 PTA 登录状态，禁止共享当前单一的 `.auth/state.json`；登录状态在服务端加密保存，密钥与数据分开管理，不返回浏览器前端、不写入日志或 Git。
- 每次任务使用独立的浏览器上下文，任务结束后关闭，防止不同用户的 Cookie 和存储串用。
- 数据至少区分：PTA 绑定记录、同步任务、题目集结果。每条记录关联业务用户；读写结果和查询任务时均校验归属。
- 通过任务队列限制全局并发，同一用户同时最多一个同步任务，避免重复点击造成并发读写状态。
- 只在完整提取成功后更新结果。网络错误、页面变化和登录失效分别报告；不将失败误报成“零个题目集”。
- 根据实际访问情况确定同步频率、超时和重试上限，避免无间隔重复请求。

### 首次登录绑定：待确认事项

服务器弹出的浏览器无法直接供远程用户操作，因此不能原样沿用当前“打开窗口、终端按回车”的流程。

优先确认 PTA 是否提供适合第三方应用的官方授权或接口；目前尚未确认，不能假设存在。若没有，需要评估用户可操作的隔离浏览器登录会话等绑定方案，并验证服务器环境下登录及验证码流程的可行性。验证码由用户本人完成，不规划绕过验证。绑定会话必须与业务用户关联，并限制有效期及访问范围。

在方案确定前，不承诺账号状态过期后可以完全无人值守重新登录。服务器也不能直接复用聊天内浏览器已有的登录状态。
